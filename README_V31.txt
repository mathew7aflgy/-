الحفلجية — V31.1 (تصحيح إدارة التيمات والتحديث الفوري)

محتويات الحزمة:
- index.html: واجهة الموقع.
- manifest.webmanifest: تعريف تطبيق PWA والأيقونات.
- sw.js: Service Worker مع إصدار cache جديد لتحديث النسخة.
- README_V31.txt: هذه التعليمات.
- icons/: أيقونات التطبيق المعتمدة.

ما تم تصحيحه في الواجهة وقاعدة البيانات:
1) استيراد مناطق التيمات القديمة من خريطة التوزيع الحالية عند إنشاء سجل التيمات لأول مرة.
2) إنشاء التيم بالاسم أولًا، ثم إضافة المناطق يدويًا.
3) إضافة المنطقة إلى تيم جديد تنزعها تلقائيًا من التيم السابق وتحدّث خريطة البحث القديمة.
4) إضافة صلاحية مستقلة باسم app_data:hf_roster_hfTeamStructure؛ لا تمنح صلاحية إدارة الأشخاص أو قوائمهم.
5) إضافة مستمع Supabase Realtime لتحديث دليل التيمات على الأجهزة المفتوحة.
6) كل تيم يحتفظ بقائمة أورجنايزرز مستقلة من خلال سجل hf_roster_<اسم التيم>.

خطوات النشر الآمنة:
1) نفّذ ملف V31_1_realtime_migration.sql المنفصل في SQL Editor قبل رفع الموقع. هذا ترحيل إضافي فقط؛ لا تعِد تشغيل SQL الخاص بـ V29.
2) بعد نجاح SQL، ارفع محتويات ZIP إلى جذر GitHub بحيث يكون index.html في الجذر، ومعه manifest.webmanifest وsw.js وREADME_V31.txt ومجلد icons. لا ترفع ملف SQL إلى جذر الموقع.
3) امنح الحسابات المختارة فقط الصلاحية المستقلة: إدارة التيمات والمناطق ونقلها. امنح app_data:hf_roster_hfTeamStructure فقط. الترحيل يمنع صلاحية app_data_prefix:hf_roster_ العامة من تجاوز هذا الفصل حتى لو كانت ممنوحة لحساب آخر.
4) اختبر بحساب المالك أولًا، ثم بحساب مفوض، ثم افتح الموقع في جهاز/متصفح آخر للتأكد من وصول التحديثات فورًا.

تنبيه مهم:
- الواجهة لا ترسم حدود GIS فعلية؛ إدارة المناطق هنا نصية/دليل توزيع.
- التحديث الفوري يعتمد على نجاح ترحيل SQL وعلى إتاحة Supabase Realtime وقراءة السجلات العامة.
- لم يتم رفع الحزمة إلى GitHub أو Cloudflare، ولم يتم تنفيذ SQL على مشروعك.
